How It Works

An LLM plays Ms. Pac-Man on a real SNES emulator (Mesen), one move at a time. The game freezes between decisions: the AI sees a raw screenshot and outputs a direction. All models run locally on Apple Silicon via mlx-vlm — no cloud APIs.

01 Freeze
Lua script saves emulator state. Game is completely paused while AI thinks.
02 See
Raw screenshot captured directly from emulator. No preprocessing.
03 Think
Vision LLM receives screenshot + prompt asking which direction has pellets and no ghosts.
04 Act
Direction sent to emulator. Game plays 45 frames (~0.75 sec). Repeat.

Key Findings

Most VLMs can't beat random moves

Only Pixtral 12B (avg 535) and Qwen2.5-VL 3B (avg 411) consistently outperform the random baseline (avg 310). The remaining 5 models all fall below — three of them dramatically so.

Bigger isn't always better

Qwen2.5-VL 3B at 411 avg outperforms its 7B sibling at 240 avg, despite being half the size and faster (3.3s vs 3.9s per move).

Some models completely fail

SmolVLM repeatedly outputs "right" regardless of game state (avg 175). Qwen3-VL 4B scores exactly 120 every game. LLaVA 1.6 fails to produce valid moves at all (avg 28). Not all VLMs can parse game screenshots into useful decisions.

Latency doesn't predict quality

Pixtral 12B is the slowest model (14.4s/move) but also the best. SmolVLM is similarly slow (10.2s) but one of the worst. The fastest model, Qwen3-VL 4B (2.6s), scores the same as doing nothing useful.
